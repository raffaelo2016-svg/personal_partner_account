# Decision Log — Партнёрский кабинет URITECH

## 1. Канонические маршруты

**Решение:** Единый вход `/login`, после логина redirect по роли: партнёр → `/dashboard`, админ → `/admin`. Маршрут `/` — технический redirect на `/login`. `AdminLogin` убирается из production route map.

- Партнёрские экраны: `/dashboard/...`
- Админские экраны: `/admin/...`

## 3. Формула расчёта судебных расходов и баннера задолженности

- **Стоимость за клиента** — фиксируется при регистрации партнёра (`partner.court_fee_per_client`, по умолчанию 15 000 ₽ = 1 500 000 копеек).
- **Начисление** — создаётся CourtFee при назначении `court_procedure_date` админом в карточке клиента.
- **Срок оплаты** (`due_date`) = `court_procedure_date` + `partner.payment_term_days` (по умолчанию 10 дней).
- **Просрочка** — CourtFee со статусом `overdue`: `due_date < today` и `status = unpaid`.
- **Общая задолженность** — сумма amount по всем CourtFee со статусом `unpaid` + `overdue`.
- **Просрочено** — сумма amount по CourtFee со статусом `overdue`.
- **Баннер:** показывается если `has_debt = true` (есть хотя бы один unpaid/overdue). Скрывается если все оплачены.
- **«Срок оплаты N дней»** — количество дней до ближайшего due_date среди unpaid CourtFee. Если все просрочены — показать количество дней просрочки.

## 4. Границы MVP

**Входит в MVP:**
- Auth (login, refresh, logout, register)
- CRUD партнёров, клиентов
- Статус-машина клиента с прогресс-баром
- Задачи (CRUD + автоматические статусы)
- Судебные расходы (расчёт + отображение)
- Генерация документов (DOCX на основе шаблонов)
- Чат (WebSocket + REST, включая AI-нейропомощника как stub)
- Уведомления (in-app)
- Обучение (видео, FAQ, инструкции — контент из seed)
- Настройки системы (key-value + notification preferences)

**Integration-ready / Stub:**
- Платёжный шлюз — заглушка (кнопка «Оплатить» → mock response)
- Email-уведомления — stub (логирование вместо отправки)
- AI-нейропомощник — stub (шаблонные ответы, если нет OPENAI_API_KEY)
- Резервные копии — stub (эндпоинт есть, реальный pg_dump — техдолг)
- Журнал безопасности — базовый (логирование login/logout, без полного audit trail)

## 5. Чувствительные ПДн (152-ФЗ)

Поля, содержащие чувствительные персональные данные:
- `passport_series`, `passport_number`, `passport_issued_by`
- `snils`, `inn` (клиента)

**Текущее решение:** хранить как есть, доступ только через сервисный слой.
**Техдолг:** шифрование AES-256 на уровне приложения.
