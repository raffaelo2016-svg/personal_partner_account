1. Что за ролик (файл, длительность, ведущий).

## 1. «БФЛ+ ПМ, внесение ЗП пенсии» (59 мин)

**Ведущая:** Анастасия Новицкая, сотрудник БФЛ+ (bfl.plus). Демонстрация в живом кабинете управляющего с 46 процедурами.

### 1.1. Как устроена их система (общие принципы)
- Позиционирование: «программа проведения процедуры БФЛ, знает логику процедуры»: какие задачи с человеком, какие — без.
- **Трёхцветная приоритизация задач:** красный — «срочно, день в день» (двигают процедуру, затягивание = искусственное удлинение срока), жёлтый — важно, но не горит, серый — фоновые; цвет меняется по мере приближения дедлайна.
- Техподдержка — значок гарнитуры (правый верхний угол); на каждой странице — инструкция (знак вопроса в голубом кружке).
- Обучение = запись встреч «действующей клиенты БФЛ», выдача точечно или полным комплексом.

### 1.2. Блок «Деньги»: авторазнесение и классификация выписок
1. **Входящая корреспонденция регистрируется сразу** («получили — зарегистрировали»): ответ, запрос, любой документ по делу → раздел «входящая почта» → дальше обработка.
2. **Регистрация выписки:** должник → дата документа → дата поступления → отправитель (банк, тип «сведение о счетах») → файл. Флаг **«разнесена / не разнесена»**:
   - секретарь только отсканировал и зарегистрировал → «не разнесена» → документ падает в «разнесение документов» для бухгалтера/юриста;
   - сотрудник внёс операции вручную до регистрации → «разнесена» → выписка просто прикладывается к отчёту, повторно не обрабатывается.
3. **«Классификация выписок»:** Excel-выписки разбираются автоматически — система сама распознаёт даты операций, подсвечивает операции **до введения процедуры** и операции периода процедуры, «без копипаста руками».

### 1.3. «Разнесение документов» (роли и источники)
- Две роли: **бухгалтер → главный бухгалтер** (проверка). Если сотрудник один — работа в режиме «без валидации».
- Сюда попадают все «денежные» документы: **ответы ФНС** (счета + имущество для сверки), **ответы СФР/ПФР** (пенсии, выплаты), **ответы работодателя**, **2-НДФЛ**, **расчётные листки**.
- **2-НДФЛ:** сумма указана без вычета 13% → перед внесением вычесть 13%.
- **Расчётный листок ценнее 2-НДФЛ:** есть даты выплат → можно отсечь суммы, полученные до введения процедуры (ПМ в неполный месяц — пропорционально дням).

### 1.4. Ручное разнесение: правила «налички»
- Операция: безнал/наличные. При «наличные» привязка к счёту скрывается.
- Кнопка **«внести несколько транзакций»** + «скопировать с предыдущей строки» — для регулярных платежей (зарплата, пенсия).
- **Правило двух операций для наличных:** 1) начисление (пенсия/зарплата), 2) **снятие должником** — та же сумма. Итог: приход 30 000 / расход 30 000 → «сошлось в ноль».
- **Изменение/удаление транзакций — только с уровня главного бухгалтера** (права разведены по ролям).

### 1.5. Расчёт ПМ (их логика, применимая в нашем блоке 15)
- Экран «иконка рубль»: соцстатус должника, количество иждивенцев, прожиток на должника и на иждивенцев.
- **Правило размера:** берётся **большее из федерального и регионального** ПМ (практика при конфликте сумм).
- **Дети и пенсионеры считаются по ПМ трудоспособного** («устоявшаяся практика, даже не повод для диспута»); иждивенцы умножаются.
- **Начисление ограничено доходом конкретного месяца** — остатки использовать запрещено (разъяснения ~2025): «суд исключает хоть 100 тыс./мес., но доход 50 → получит 50».
- Неполный месяц — ПМ пропорционален дням.
- **Соцстатус (самозанятый/работающий/безработный) не влияет на расчёт** — это только точка контроля (какие документы запросить: электронная трудовая и т.п.); расчёт идёт от фактических поступлений по выписке.
- Пересчёт ПМ фоновый (2–3 мин) — их ответ на жалобы о медленном просчёте: «не сиди и не жди, делай другие задачи».
- Колонки сводки: начислено / снято должником / выплачено должнику / алименты (2 кол.) / найм жилья (3 кол.) / исключено судом / приход не в КМ.

### 1.6. Исключения из конкурсной массы
- **Приход не в КМ:** алименты, пособия, компенсации — заносится сразу при разнесении выписки (отдельная пометка операции).
- **Исключено судом:** «Валидация соцположения» → «Валидировать соц. статус и иждивенцев» → поле «исключено судом»: **сумма + периодичность (ежемесячно/единоразово) + дата начала начисления**. Ежемесячное исключение добавляется к начисленному ПМ сверху, но также ограничено доходом месяца.
- Валидация соцположения — отдельный статус (жёлтая плашка, пока не валидировано).

### 1.7. Связь с отчётами
- Ошибка в транзакциях при подготовке квартального/итогового отчёта → правится **в системе**, затем кнопка **«перегенерация»** отчёта → снова проверка → только потом валидация. Порядок жёсткий: проверка → перегенерация → валидация.

### 1.8. Q&A — нестандартные кейсы (важно для логики нашего калькулятора)
- **Отпускные** (учителя: оклад за 3 месяца в мае). Два легальных способа: 1) разбить транзакцию вручную по месяцам отпуска (нужен приказ на отпуск с датой окончания) — программа начислит ПМ каждый месяц; 2) через «исключено судом/из КМ»: в мае исключить всю сумму, выдать человеку, летом — по нулям. БФЛ+ признаёт, что автоматического режима у них нет — «не дорабатывали раздел после изменений».
- **Алименты/удержания:** иждивенцы делятся на категории: дети, «трудоспособный» (супруга в декрете), дети + трудоспособный; размер алиментов 1/4, 1/3 и т.д. — начисляется пропорцией от дохода. Вариант «алименты платит работодатель» → ПМ и алименты = 0, помечается «удерживает работодатель». Удержание по исполнительному листу = операция «списание кредитора», на расчёт ПМ не влияет. Профсоюзные взносы — на усмотрение управляющего.
- **Конец декабря / майские** (зарплата пришла досрочно): дату транзакции ставят 1 января/первым рабочим днём месяца — чтобы ПМ начислился в правильном месяце; при вопросах — обосновывается.
- **Раздел «Оплачивание»:** ежемесячный реестр «кому выплатить ПМ»: заявление на выдачу прожитка, способ получения (перевод на третье лицо / почтовый перевод), QR-код реквизитов. Работает по запросу, не автоматически; >90% клиентов перешли на «согласие», раздел отмирает.
- **Слабое место конкурента (их признание):** уведомления кредиторам при введении процедуры должны стартовать вместе с публикациями и запросами («втроём»), но у них модуль уведомлений даёт сбои, техподдержка чинит. → наша возможность: сделать блок 5 (уведомления) надёжным стартовым пакетом.

## 2. «БФЛ банки счета контрагенты» (34 мин)

**Ведущая:** Анастасия Новицкая (БФЛ+). Кабинет управляющего: 47 процедур + 15–16 на утверждение кандидатуры.

### 2.1. Организация обучения конкурента
- Обучение в режиме «живого» кабинета, встречи понедельник–четверг; Telegram-канал с **разнарядкой тем на неделю вперёд**, темы с повторами (циклические задачи, напр. РТК).
- Для клиентов: чат обучения, **персональное видеообучение на примере их дел**, инструкция на каждой странице системы; техподдержка отдельно от обучения.

### 2.2. Раздел «Банки – счета – контрагенты» (их блок 7)
**Кому:** бухгалтерам или юристам с бухгалтерским опытом (финансовый подтекст: 2-НДФЛ, расчётные листы, «пенсионный квиточек»).

1. **Основной счёт должника** — обязателен при переходе дела в статус процедуры (реализация / реализация после реструктуризации). Система сама ставит задачу, если основного счёта нет; выбор: из уже занесённых счетов или открыть свой и внести реквизиты с пометкой «основной». Нужен для генерации **требования о переводе дохода** (работодателю/плательщикам) — без него система откажется формировать требование.
2. **Интеграция с банком:** в тестировании — сопряжение с **Совкомбанком** (автооткрытие счетов: документы уходят в банк, открытые счета возвращаются в систему; несколько клиентов на пилоте).
3. **Разблокировка счетов и получение выписок:** кнопки «разблокировка запрошена» / «выписка запрошена» → задачи падают на профильные страницы. Сбер — визит в отделение (паспорт + доверенность), Почта Банк / Т-банк — по письмам; генератор документов содержит заявления по банкам (выписка, разблокировка, закрытие). Статусы «подано [дата]» → контроль ответа; после внесения операции/остатка задача снимается.
4. **Проблемные счета:** причина, почему работа со счётом невозможна, падает отдельным списком.
5. **«Работа в банках»:** внесение операций онлайн (остаток / снятие ФУ), общая сумма для кассы; **авторазнесение «снятие ФУ»** → меняет остаток денег у ФУ (иконка «рубль»).
6. **Классификация выписок:** просить банки выдавать выписки **в Excel** (Сбер, Альфа, ВТБ, Совкомбанк и др.) — экономия на печати и сканировании; регистрация: должник → даты → отправитель → вид «сведение о счетах в выписке» → файл Excel без конвертации → статус «не разнесена»; система читает файл, операции периода процедуры предлагает подтвердить и разнести.
7. **Разнесение документов, две страницы:** с валидацией (бухгалтер → главбух: результат «разнесено» или «есть вопросы» — падает главбуху; проверка «по диагонали»: 10 счетов в ответе → все 10 внесены) и **без валидации** (одиночки: кнопка «документ обработан» + дата; закрытие синхронизировано со страницей с валидацией).
8. **«Разрешение по счетам в РД» (реструктуризация долгов):** партнёр-юрист из своего ЛК подаёт «заявление на разрешение» (счёт, банк, адрес) → у ФУ запрос → в картотеке генерируется разрешение → отправка исходящей почтой, **номер РПО заносится в систему** → партнёр видит «разрешение направлено, РПО, дата». Мета-цель: исключить переписку в мессенджерах, всё видно обеим сторонам.

### 2.3. Слабое место конкурента (их признание)
- Клиент жалуется: по **залоговому счёту** (приход от продажи имущества + расходы: вознаграждение ФУ, перевод кредитору) классификация не имеет типа «расходы-вознаграждение» — система дважды распознала операции как расходы. Ведущая признаёт: «технический момент, передам разработке». → Наша возможность: с первого дня заложить корректную типизацию операций спецсчёта (вознаграждение, перечисление залоговому кредитору 80%, кредиторам 1–2 очереди 10%, расходы) — это блоки 16 и 17.

## 3. «Логика БФЛ+» (внутренний документ вендора, 24 пункта)

Документ из папки конкурента (`Логика БФЛплюс.docx`) — полное описание архитектуры конвейера. Главное:

### 3.1. Четыре потока данных и рождение задач
1. **Черновик дела** (заполняется в ЛК партнёра/сопровождения или ЛК управляющего: должник, имущество, обязательства, иждивенцы) → после присвоения судом номера дела черновик «передаётся управляющему» → задача **«Процедура – Валидация новых дел»** (принять или вернуть на доработку).
2. **КАД** — судебные акты скачиваются автоматически, проходят анализ алгоритмами и ИИ, попадают на две страницы: **«Проверка наличия требований в РТК»** (акты по требованиям) и **«Разбор КАД»** (остальные акты).
3. **Входящая почта** — регистрируется в единой точке (отправитель → вид документа → дело) и автоматикой распределяется: входящие новые → классификация выписок (xlsx: Альфа, ВТБ, Газпромбанк, Контур-Банк, Сбер, Совкомбанк, Россельхозбанк) → разнесение документов → РТК «поступило требование кредитора».
4. **Документы партнёра** — из ЛК партнёра/сопровождения → «Документооборот – Валидация документов».

**Мониторинг дела:** автоматика читает акты и заполняет ключевые даты: без движения / дата СЗ по введению процедуры / даты резолютивной и «в полном объёме» / дата СЗ по отчёту управляющего / отложения → формирует задачи. При сбоях — страховочные ручные задачи: «Обновить дату СЗ по введению процедуры» (прошло 2 дня), «Обновить дату итогового СЗ», «Заполнить колонки», в РТК — «Дата рассмотрения требования», «Актуализация РТК», «Валидация актуализации РТК».

### 3.2. Ключевые автоматики (чего у них добились)
- **Согласие в СРО генерируется и подаётся автоматически** (условия: опубликован судакт о назначении даты СЗ + дата заполнена; при авансовом режиме — подгружена квитанция). Отказ → задача «Не отправлено согласие в СРО».
- **Публикации ЕФРСБ** генерируются по условиям (дело в процедуре + «Заполнить колонки» + валидированы данные должника); собрание — после валидации даты и повестки. **«Коммерсантъ»:** счёт запрашивается автоматически → QR-код на оплату → «Оплачено» → расход внесён автоматически → через 3 дня задача «Ъ Опубликовано».
- **Уведомления о введении процедуры** формируются автоматически (дело в процедуре + валидированы кредиторы); новый кредитор → авто-уведомление.
- **Запросы** генерируются автоматически по должнику и супругу/бывшим супругам (с автоподклейкой документов родства и судебных актов); получатели — из настроек; новый супруг → авто-дозапросы.
- **Сразу после введения процедуры** — две задачи: «Проверка наличия сделок» и «Проверка наличия имущества» (по имеющимся документам, не дожидаясь госорганов).
- **Почта:** письма одного получателя у одного управляющего объединяются, РПО/конверты/реестры — автоматически, формируются почтовые партии; ЭЗП — подгрузил *.sig → отправка сама; НСИС и прочие сайты — ручная отправка с отметкой (автоотправка недоступна).
- **Сделки:** любая внесённая сделка → задача «нужен ли анализ» → маршрут: изучение → заключение → стадии оспаривания.
- **Торги:** любое имущество → стандартный маршрут: фото → оценка → положение → старт → мониторинг → результаты → договор и оплата; исключено из КМ — задачи не создаются; нет имущества — розыск/истребование через суд.
- **Списания ФССП и кредиторов:** система видит удержание при разнесении выписок → отдельная задача «Направить уведомление» (в ведомство или кредитору). Это и есть модуль «Списание ФСС» из скриншотов.
- **ПМ:** заявление на ПМ/алименты/найм жилья регистрируется в ЛК партнёра или добавляется из почты → приёмка → система сама считает сумму и ставит к выплате **QR-кодами** (по мере разнесения выписок, при положительном остатке).
- **Расходы:** каждое действие оплаты автоматически создаёт расход; подтверждающие документы авто-подклеиваются к отчётам; **резерв на 2 публикации после завершения** добавляется автоматически.
- **Квартальные отчёты:** раздел «К выполнению» появляется **за 11 дней до конца квартала**; авто-сборка → проверка → отправка (или полная авто-отправка по настройке).
- **Итоговые отчёты:** «Все» и «Срочно» (подача в ближайший месяц); тип отчёта предлагается автоматически, если дело готово (торги закрыты, требования рассмотрены, споров нет).
- **Собрания кредиторов:** в реструктуризации собрание создаётся системой сама; валидация даты и повестки → публикации, рассылки, документы.
- **Жалобы на управляющего:** страница «Жалобы ФУ» — ручной ввод сути, требований, дат.
- **Завершение/архив:** авто-итоговые публикации и загрузка отчётов; дело в архиве остаётся доступным; если дело невозможно провести (оставлено без рассмотрения / другой управляющий) — архив с **возвратом списания за процедуру** (процедура возвращается на баланс).

### 3.3. Философия конвейера
«Сотрудники заходят не в дела, а в боковое меню задач → закрывают задачи → система сама ведёт процедуру до отчётов и завершения». Валидация («один внёс, второй проверил») — фундамент автоматики: ошибки в данных должника/соцположения/кредиторов ломают все сценарии дальше.

## 4. Питч-дек «Автоматизация арбитражного управления в БФЛ» (30 слайдов)

- **Масштаб:** 7000+ процедур, 1500 дел в работе, 130 дел/мес завершается, средний срок 7,5 мес. Анна Рыбникова: с 2019 >2100 дел, с 2021 >4500 дел (видимо, суммарно по команде).
- **Экономика исполнения:** 15,92 ч/дело, из них юристы — 1,07 ч (6,7% времени, 14% ФОТ); операционисты — 7,6 ч, помощники/секретари — 7,2 ч. Стоимость персонала — **3316 ₽/процедура**.
- **Сравнение затрат:** «классика» (ФОТ 25 помощников + ПАУ «Профессионал» 58 580 ₽ + доп. места по 10 980 ₽ + CRM Битрикс ~100 000 ₽ + сервер ~120 000 ₽) = **12 200 ₽/дело**; их модель (ФОТ + БФЛ+) = **4 316 ₽/дело**; экономия ≈ 7 900 ₽ × 1500 дел ≈ **11,8 млн ₽/год**.
- **Метрики модулей:** госзапросы 10 шагов → 2 (40 мин → 5 мин/дело, −8,3 раб. дня на 100 делах/мес); квартальные отчёты 815 дел/72 ч → 933 дела/22 ч (−70%); ЛК −87% времени, ×8 скорость; авторасходы −30% трудозатрат на итоговых отчётах; ручной учёт расходов = потери (на 100 делах: 2 потерянных письма −15 800 ₽/мес, бумага −25 000 ₽/мес).
- **Система контроля персонала:** каждый час учтён, каждое действие логировано, подсветка неэффективных, «контроль приписок» (отработанное время vs данные автоматики).
- **Роадмап «Операционный автопилот»:** 2025–нач. 2026 — строгая логика; 2026 — нейросеть: автоотправка ЭЗП в 1 шаг, автооткрытие счетов в Совкомбанке (myfu.ru), автоматизация выдачи разрешений по счетам, **импорт обязательств из БКИ**, обучение на сценариях операционистов, **анализ сделок и поиск аномалий**, **оценка имущества**.

## 5. Telegram-канал конкурента: позиционирование, кейсы, тарифы

Источник: `БФЛ+ телега.docx` (посты канала). Ключевое:

### 5.1. Тариф и модель
- **«Стоимость БФЛ+: от 1000 до 2000 ₽ за процедуру»**, полная автоматизация уведомлений включена, без доплат за сотрудников. Рабочие места не лицензируются: «количество управляющих не ограничено, партнёры в своих кабинетах, вся команда подключается без доплат», работа через браузер, «без IT-внедрения».

### 5.2. Маркетинговые кейсы (их аргументация)
- **Коммерсантъ вручную = потери:** 40 дел → 7 часов сотрудника → 39 завышенных счетов → переплата 102 421 ₽; через БФЛ+ те же 40 дел = 15 минут.
- **ЕФРСБ — зона штрафов:** письмо СРО от 30.07.2024: 1222 отчёта не опубликованы вовремя, 71 управляющий в списке нарушений; у первых 20 — 1109 просрочек.
- **Дисквалификации:** «в 2023 каждый седьмой из ТОП-450 потерял статус» — крупные команды на ручном контроле.
- **Отзывы на требования в РТК:** >95% требований без возражений; маршрут: сверить с КАД → дата заседания → сгенерировать отзыв → отправить кредитору → доказательства в суд; юрист отвечает на один вопрос «возражаем или нет», остальное — автоматика.
- **Уведомления кредиторов — 15 дней** (их трактовка срока): данные кредиторов собираются в черновике до подачи, валидация — сценарием, генерация с подписью ФУ без ручной подписи, группировка повторяющихся кредиторов в один конверт, РПО через API Почты, отслеживание движения, автофиксация расходов.
- **Собрания кредиторов:** сценарий после закрытия реестра, проверка кворума, заочная форма по умолчанию, авто-повестка, протокол подшивается к отчёту.
- **Финанализ (АФС):** «шаблон на 2–3 листа, не диссертация»; 20 минут работы помощника; очередь «дела без финанализа», задача краснеет, если до первого заседания < 2 месяцев; авто-публикация итогов в ЕФРСБ и подшивка к отчёту.
- **Разбор КАД с ИИ:** раз в сутки сбор актов, ИИ типизирует и описывает «что требуется от управляющего», «недовольство суда» помечается красным; акты по требованиям — сразу в РТК; даты заседаний — в календарь.
- **CD-диски для квартальных отчётов:** третий путь для кредиторов без email — комплект отчёта на диске с сопроводительным, РПО и расходами в отчёт (815 дел → 2 дня → 2 секретаря).
- **Телефонная нагрузка:** отдельная SIM под Госуслуги, переадресация на помощников; 70–80% звонков исчезают, потому что система закрывает причины (отчёты в КАД, отзывы поданы, запросы отправлены).

### 5.3. Организация «фабрики процедур» (их операционка)
- Роли: операционист / помощник-секретарь / юрист; «люди не ведут дела — работают с очередями задач, не с карточками дел».
- Подбор: Avito (эффективнее юрсайтов «в десятки раз»), тест скорости набора текста, требования к рабочему месту: экран ≥ 1920×1080 (двойная рабочая область — «критично»), Windows 10+.
- Почта: курьер 3 раза в неделю (срок хранения судебных писем — 5 дней), поточный сканер Canon imageFormula DR-C225, датёр; сортировка конвертов: Интерфакс (не вскрываются) / суд / иные; исполнительные листы — в персональные файлы, ПТС/СТС/ключи/карты — в папки «Торги»/«Карты».
- Доверенности: консульский отдел за рубежом, $60–100 за консульскую доверенность на все дела (80 листов у одного ФУ).

### 5.4. Партнёрский ЛК (их b2b-контур)
- Бесплатный генератор шаблонов: партнёр сам запускает черновик после подписания договора; формирует заявление, опись имущества, список кредиторов; неограниченное число черновиков.

## 6. Видео-тур БФЛ+ (53 мин, полный обход интерфейса)

Полная запись продающей демонстрации для управляющих/компаний.

### 6.1. Личный кабинет партнёра (бесплатный для партнёра)
- Черновики: заявление, опись, список кредиторов генерируются из данных; прогноз «реструктуризация vs реализация» — система предупреждает, если по доходу прогнозируется реструктуризация и нужно обоснование.
- Минимум для передачи дела — 6 документов; кнопка «Передать».
- Витрина данных: ход подачи, кандидатура, ночной обход КАД, «что нужно от всех для завершения», «сделать для завершения» (фото, пояснения), вопросы к ближайшему заседанию (завершение/отложение), расчёт ПМ с детализацией.
- Чат по делу с темами (деньги, торги), задачи красным = просрочка, документы по фамилии должника; доступы сотрудникам с блокировкой при увольнении.

### 6.2. Кабинет управляющего
- Боковое меню задач по потокам: «публикации ЕФРСБ — 59 штук сегодня», «итоговые отчёты — 11», «исходящие» — у секретариата. Сотрудник работает с очередями, не с делами.
- 4 цвета: голубой = новости, красный = ежедневное, жёлтый = после красных, серый = срок не наступил/нет триггера.
- Приём дела: «Валидация новых дел» → картотека (интеллектуальный поиск: «ндфл 20.10») → «принять в работу» → списание с баланса («до 1000 ₽ за процедуру на 18 месяцев»).
- Несколько управляющих в одном кабинете, общий пакетный баланс (разбить баланс по управляющим система пока не умеет — их признанный недочёт).
- Иконки материалов дела: файлы/картотека, запросы, входящие, госзапросы, РТК, имущество, сделки, деньги, чат.

### 6.3. Мониторинг КАД и разбор судактов (их ИИ)
- Еженощная сверка; согласие в СРО направляется автоматически при принятии заявления (обмен по email), система читает, зарегистрировал ли суд ответ СРО.
- В 90% случаев система сама понимает введённую процедуру, сроки, вид и проверяет назначение управляющего; при неуверенности — задача «Заполнить колонки».
- ИИ обучается на лайках/дизлайках; «особое внимание», если суд интонирует, повторно пишет про штраф или просит нетипичный документ; стандартные поручения суда → «поручение управляющему».
- РТК-акты — в отдельный раздел: система распознаёт и подсказывает по очередностям, но **сама не вносит** — человек сверяет глазами; после проверки — авто-задачи на публикацию.

### 6.4. Отзывы на требования (их кейс автоматизации)
- Суд принял требование → задача «подать отзыв»; 90–95% отзывов без возражений; проверка 1–1,5 мин (список кредиторов vs заявленное, сроки давности) → «подтвердить» → отзыв по шаблону → робот отправляет по email или секретарь почтой; РПО → трекинг на сайте Почты → отчёт подшит к отзыву → задача «подать отзыв в КАД». Цепочка «закрыл одну задачу — появилась следующая».

### 6.5. Публикации: Коммерсантъ и ЕФРСБ
- Коммерсантъ: запрос по email вшитым шаблоном (полное наименование СРО — были дисквалификации за сокращения); чек 8 400–9 100 ₽; QR-код → «Оплачено» → расход в реестр и отчёт + задача подгрузить платёжку.
- ЕФРСБ: авто-задачи по всем триггерам (сделки, собрания, требования РТК); **черновиков нет — перенос текста вручную на два экрана** (их признанный минус vs ПАУ, где черновики есть).

### 6.6. Квартальные и итоговые отчёты
- Авто-квартальные (настройка: отметить включаемые документы): все формы (новая + ЕФРСБ + 4.5 по реализации — старые оставили, т.к. суды привыкли, в новой нет контрольных цифр), приложения сшиты, кредиторам с email уходит автоматически; Q4: 900+ дел = 6 часов помощника + 2 дня секретарей на диски.
- Итоговый: система предлагает итоговый/промежуточный по признакам (незавершённые обособленные споры, торги, имущество в розыске → промежуточный); подсказки («денег нет даже на расходы»); единственный редактируемый файл — ходатайство в суд (DOC); правки — в систему, затем перегенерация (5 сек – 15 мин).

### 6.7. Запросы и уведомления
- Настройки запросов по управляющим: зелёные — авто по всем делам/регионам (должник + супруг), серые — по кнопке (БТИ и др.); новый супруг → авто-дозапросы; способы: ЛК органа (Росреестр, НСИС) или почта.
- Уведомления кредиторам — только Почтой России, генерируются автоматически.

### 6.8. Почта
- Почтовые партии: настройка дней отправки, печать конвертов, красный статус «не распечатано»; **склейка писем по адресату** (5 должников → 1 конверт в ГИБДД региона, 1 РПО — дешевле); марочная отправка, в тестировании — знак оплаты (QR на конверте, бизнес-аккаунт Почты).
- ЭЗП: лимит 19 листов (запрос на должника + супруга с полным судактом ≈ 10 стр., второй запрос не пришить); отправка через Госуслуги вручную → РПО → трекинг.

### 6.9. ПМ и выплаты (сводно, поверх ролика №1)
- Ставки из актуализируемого справочника; регион < РФ → ставка трудоспособного РФ; ребёнок — **полный** прожиток (не половина); алименты и аренда жилья (текущий платёж) рассчитываются здесь же.
- Выплата: реквизиты из заявления на прожиток, «оплачено» → отчёт о движении денежных средств.
- Один документ — один файл при регистрации входящих (тип документа определяет маршрут задач).

### 6.10. Их утверждения о конкурентах
- «Пытались повторить и Low Business Group, и Club 127 — никто не сделал» (про объём автоматизации).
- ПАУ: 20+ лет, акцент на банкротство юрлиц, витрина «скудная», задачи ведутся вручную по списку.
