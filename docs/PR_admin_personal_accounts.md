# PR: персональные учётные записи админов и агентский кабинет

## Что и зачем

Сотрудники больше не работают под одной общей учётной записью: у каждого личный вход, приглашение и запись в журнале. Параллельно запускается агентская программа: агент приводит партнёров, получает 1 000 ₽ за клиента, дошедшего до процедуры.

Партнёрский кабинет не менялся: вход и экраны партнёров работают как раньше.

## Что внутри

### Доступы сотрудников

- Роль `super_admin`, роль `agent`; вход по почте или логину.
- Первый запуск по одноразовому ключу: `python -m app.scripts.create_bootstrap_key`.
- Приглашения: почта + роль + срок 24/72/168 ч, одноразовая ссылка, отзыв и перевыпуск, копирование ссылки из списка.
- Регистрация по приглашению; для агента дополнительно ФИО и телефон.
- Блокировка, смена роли, защита последнего супер-админа.
- Сброс пароля завершает старые сессии.
- Капча после 3 неудачных входов, блокировка на 15 минут после 5.
- Журнал: входы, приглашения, роли, привязки, начисления, выплаты; фильтры «Доступы» и «Агенты и деньги».
- Очистка журнала старше 365 дней: `python -m app.scripts.cleanup_audit`.

### Агентский кабинет

- Реферальный код и ссылка `/register?agent=КОД`.
- Закрепление партнёра за агентом при регистрации; ручная перепривязка в карточке партнёра с причиной.
- Начисление 1 000 ₽ при переходе клиента в «введение в процедуру»; одно дело — одно начисление.
- Корректировка начисления админом (отмена/возврат) с причиной и записью в журнал.
- Реквизиты и их проверка; заявки на выплату со статусами и циклом 14/15 числа.
- Кабинет агента: главная, партнёры, начисления, выплаты, реквизиты, материалы, поддержка.
- Уведомления в кабинете: начисление, статус выплаты, реквизиты.
- Материалы: презентация PDF, два баннера, готовые тексты с подставленной ссылкой.

### Миграция

`python -m app.scripts.migrate_shared_account` — находит общую учётку, создаёт приглашения, отключает общий вход. Репетиция на копии базы описана в `docs/Прод-запуск_и_поддержка.md` (данные партнёров и клиентов не меняются, партнёрский вход работает).

## Переменные окружения

Новых обязательных нет. Для писем — `SMTP_*` или `RESEND_*`; проверка:

```bash
python -m app.scripts.check_email --to адрес@uritech.ru
```

## Проверка

- Backend: тесты доступов, капчи, агентского кабинета, партнёрские наборы — проходят (в CI на PostgreSQL и Redis).
- Frontend: `tsc --noEmit`, `vite build`.
- Вручную: входы всех ролей, приглашение агента, регистрация партнёра по ссылке, начисление, реквизиты, заявка, выплата, корректировка, журнал.
- Отдельно проверен вход существующих партнёров (логин пустой, вход по почте) — не нарушен.

## Риски и что учесть

- Партнёрский контур затронут минимально: в списках партнёров фильтр стал явным (`role = partner`), поведение для существующих данных то же.
- Почта должна быть настроена до запуска приглашений; без неё ссылку передают вручную.
- Общую учётку отключать только после уведомления сотрудников за 5 рабочих дней.
- 2FA не входит; частичных выплат нет.
