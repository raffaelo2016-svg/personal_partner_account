# Этап 4. Клиенты: контакт и сделка

Статус: реализация безопасного контура первой версии.

## Что создаётся

При создании нового клиента кабинет последовательно создаёт:

1. контакт Битрикс24;
2. сделку в воронке «АРБИТРАЖ» (`categoryId=3`, стадия `C3:NEW`);
3. связь сделки с контактом и смарт-процессом партнёра.

Обе записи получают внешний UUID клиента и источник `partner_cabinet`. Перед созданием выполняется поиск по этим полям, поэтому повтор обработки не создаёт дубль.

## Передаваемые данные

В контакт передаются ФИО, телефон, электронная почта и дата рождения. В сделку передаются тип и статус клиента, регион, арбитражный суд, номер дела и дата судебной процедуры.

Паспортные данные, ИНН, СНИЛС и адрес регистрации не передаются. Кабинет не меняет стадии сделки после её создания.

## Новые поля сделки

- `UF_CRM_YRITECH_CLIENT_REGION`;
- `UF_CRM_YRITECH_ARBITRAGE_COURT`;
- `UF_CRM_YRITECH_CASE_NUMBER`;
- `UF_CRM_YRITECH_COURT_DATE`;
- `UF_CRM_YRITECH_CLIENT_TYPE`;
- `UF_CRM_YRITECH_CLIENT_STATUS`.

Проверка наличия полей (без изменений):

```bash
python -m app.integrations.bitrix24.client_setup_cli
```

Создание отсутствующих полей:

```bash
python -m app.integrations.bitrix24.client_setup_cli --apply
```

## Повторы и восстановление

Операции записываются в надёжную очередь. Временные ошибки повторяются с увеличивающейся задержкой. Администратор может повторить окончательно неудачную синхронизацию запросом `POST /admin/clients/{client_id}/bitrix/retry`.

Существующие клиенты автоматически не переносятся. Клиент, созданный во время синхронизации партнёра, ждёт её завершения и затем отправляется автоматически.
