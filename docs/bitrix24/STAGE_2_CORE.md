# Этап 2. Интеграционное ядро Битрикс24

Статус: реализован базовый безопасный контур.

Дата: 2026-08-01.

## Что реализовано

- долговечная очередь исходящих REST-операций в PostgreSQL;
- состояния `pending`, `processing`, `completed`, `retry`, `failed`;
- идемпотентный ключ операции, исключающий повторное создание одной задачи;
- ограниченные повторные попытки с экспоненциальной задержкой;
- повтор OAuth-запроса после безопасного обновления истёкшего токена;
- получение токена только из зашифрованного хранилища;
- журнал входящих событий без хранения тела события и учётных данных;
- защита от повторной обработки события;
- защита от циклов через `ORIGINATOR_ID=partner_cabinet`;
- таблица связей локальных и удалённых сущностей;
- восстановление операций, оставшихся в `processing` после сбоя;
- периодическая проверка устаревших связей;
- структурированные журналы без токенов, персональных данных и тела REST-запросов.

## Безопасные ограничения первой версии

- паспортные данные, ИНН и СНИЛС не ставятся в очередь;
- стадии сделок не меняются автоматически;
- синхронизация не запускается для всех существующих записей;
- пользовательские поля `YRITECH` создаются отдельной контролируемой операцией;
- ответственный сотрудник передаётся только из настраиваемого справочника.

## Фоновые процессы

- очередь проверяется каждые 15 секунд;
- прерванные операции освобождаются каждые 5 минут;
- после восьми неудачных попыток операция получает окончательный статус `failed`;
- задержка между попытками растёт от 30 секунд до одного часа.

## Следующий прикладной контур

После публикации ядра можно подключать адаптеры сущностей по одному:

1. партнёр → смарт-процесс;
2. клиент → контакт и сделка;
3. задача → задача Битрикс24;
4. документы → Диск;
5. чат и уведомления.

Каждый адаптер должен использовать таблицу соответствия полей, очередь исходящих операций и таблицу связей,
а не выполнять REST-запись непосредственно из пользовательского HTTP-запроса.
