# Этап 3. Активация партнёра и проекция в Битрикс24

## Что реализовано

При создании активного партнёра или переходе партнёра из другого статуса в `active`
кабинет ставит в транзакционную очередь единственную операцию `crm.item.add`.
Повторные запросы не создают дубли: используется постоянный ключ операции и таблица
соответствия локального UUID удалённому элементу.

В смарт-процесс Битрикс24 передаются только согласованные данные:

- UUID партнёра;
- название и тип партнёра;
- ФИО руководителя;
- телефон и email;
- ИНН и КПП;
- стоимость клиента и срок оплаты;
- юридический адрес, если он заполнен.

Кабинет остаётся источником истины. Входящее событие изменения элемента в
Битрикс24 переводит синхронизацию в статус `conflict`, но не меняет реквизиты
партнёра автоматически.

## Коллаба

Автоматическое создание коллабы не включено: для используемой конфигурации не
подтверждён стабильный публичный REST-метод. После создания элемента партнёр
получает статус `binding_required`. Администратор вручную указывает ID коллабы,
чата и корневой папки на карточке партнёра.

Отсутствие привязки не блокирует вход партнёра в кабинет. До привязки недоступны
только будущие сценарии обмена задачами, файлами и сообщениями через Битрикс24.

## Первичная настройка портала

Команда настройки по умолчанию выполняет безопасную проверку. С флагом `--apply`
она создаёт пять недостающих пользовательских полей смарт-процесса и подписывает
обработчик на `ONCRMDYNAMICITEMUPDATE`. Токен читается из зашифрованного хранилища;
секреты и реквизиты партнёров в вывод не попадают.

Для текущего мигрированного on-prem портала конфигурация пользовательских полей
использует внутренний идентификатор `CRM_16`, хотя REST-тип смарт-процесса —
`1070`. Исторические поля сохранили префикс `UF_CRM_31_`, а новые поля портал
принимает только с префиксом `UF_CRM_16_`.

```bash
python -m app.integrations.bitrix24.partner_setup_cli
python -m app.integrations.bitrix24.partner_setup_cli --apply
```

## Состояния синхронизации

- `not_scheduled` — партнёр ещё не активирован либо активная установка Битрикс24 не найдена;
- `pending` / `processing` — операция ожидает или выполняется;
- `synced` — элемент создан, его ID сохранён;
- `failed` — исчерпаны повторы или удалённый ID не получен;
- `conflict` — профиль изменён на стороне Битрикс24 и требует решения администратора.

## Эксплуатационные ограничения

- существующие партнёры не выгружаются задним числом;
- паспортные данные не передаются;
- токены не копируются в команды и не выводятся в журналы;
- повтор синхронизации доступен администратору из карточки партнёра.
