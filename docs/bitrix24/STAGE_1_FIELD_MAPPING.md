## Решения полного контура

1. Создание отдельных полей `YRITECH`, так как названия многих существующих полей дублируются.
2. Начальные стадии: `DT1070_19:NEW` для партнёра и `C3:NEW` для сделки.
3. Правила назначения ответственных по типам задач.
4. Передачу паспортных данных и модель доступа к ним.
5. Соответствие восьми статусов клиента кабинета со стадиями воронки. До согласования сделка создаётся только в `C3:NEW`, а её стадия не меняется кабинетом.

До отдельного утверждения полного контура перечисленные расширения не включаются автоматически.

## Утверждённое решение первой версии

- используются отдельные поля `YRITECH`, чтобы не связывать интеграцию с неоднозначными дублями;
- начальные стадии: `DT1070_19:NEW` для партнёра и `C3:NEW` для сделки;
- ответственные по задачам задаются настраиваемым справочником, без жёстко заданного сотрудника;
- паспортные данные не передаются;
- ИНН и СНИЛС не передаются до отдельной проверки модели доступа;
- кабинет не меняет стадии сделки до утверждения полного соответствия восьми статусов;
- интеграция начинает работу только с новыми или отдельно выбранными записями.

Это решение разрешает разработку интеграционного ядра и безопасных сценариев первой версии. Создание полей
в продуктивном Битрикс24 выполняется отдельной контролируемой операцией перед включением синхронизации партнёров.
