# Этап 5. Задачи Битрикс24

Статус: безопасный контур первой версии.

## Что синхронизируется

Новая задача кабинета ставится в надёжную очередь и создаётся в Битрикс24 после синхронизации клиента. В задачу передаются:

- название и описание;
- срок;
- приоритет;
- настроенный ответственный;
- настроенные наблюдатели;
- связь со сделкой клиента;
- внешний UUID для защиты от дублей.

Существующие задачи автоматически не переносятся.

## Ответственные

Числовые ID сотрудников не зашиты в код. Для ролей кабинета используются настройки:

- `bitrix_task_responsible_partner`;
- `bitrix_task_responsible_admin`;
- необязательный создатель — `bitrix_task_creator_id`.
- наблюдатели — `bitrix_task_auditor_ids` (ID через запятую).

Если для роли нет активного сотрудника, задача остаётся в кабинете со статусом `not_scheduled` и кодом `RESPONSIBLE_NOT_CONFIGURED`. Случайное назначение не выполняется.
После настройки ответственного такую задачу нужно повторно отправить кнопкой повтора в кабинете или запросом `POST /api/v1/tasks/{task_id}/bitrix/retry`.

Проверка конфигурации без изменений:

```bash
python -m app.integrations.bitrix24.task_setup_cli
```

Сохранение проверенных ID и подписка на обновление задач:

```bash
python -m app.integrations.bitrix24.task_setup_cli --apply \
  --partner-responsible-id 54 --admin-responsible-id 54 --creator-id 1509 \
  --auditor-ids 56 55 43
```

При первой производственной выкладке незаполненные роли безопасно направляются
пользователю, который установил интеграцию. Уже настроенные роли при следующих
выкладках не перезаписываются. Одновременно обеспечивается подписка на
`OnTaskUpdate`:

```bash
python -m app.integrations.bitrix24.task_setup_cli --apply \
  --fill-missing-with-installer
```

## Обновления задачи

Исполнением синхронизированной задачи управляет Битрикс24. Событие `OnTaskUpdate` содержит только ID задачи, поэтому кабинет запрашивает актуальную карточку через REST и обновляет название, описание, статус, приоритет, срок и известную роль ответственного.

Для статуса применяется безопасное соответствие:

| Битрикс24 | Кабинет |
|---|---|
| ожидает выполнения | `pending` |
| выполняется | `in_progress` |
| ожидает контроля | `in_progress` |
| завершена | `completed` |
| отложена | `pending` |

Необработанное событие хранит только технический ID задачи и повторяется фоновым процессом. Дополнительно общий процесс сверки каждые пять минут выбирает ограниченную пачку давно не проверявшихся связей и заново читает карточки задач. Так пропущенное событие не оставляет данные кабинета устаревшими. Тело события, комментарии и персональные данные не сохраняются.

## Ограничения первой версии

- кабинет создаёт задачу, но не перезаписывает её статус в Битрикс24;
- после создания задачи локальное изменение статуса блокируется: источником статуса становится Битрикс24;
- локальные изменения названия, описания, приоритета, срока и ответственного не отправляются в Битрикс24 и могут быть заменены данными основной системы при следующей сверке;
- удаление локальной задачи не удаляет задачу Битрикс24;
- комментарии и файлы будут подключаться на следующих этапах.
