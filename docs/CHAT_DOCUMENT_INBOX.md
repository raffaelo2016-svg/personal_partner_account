# Документы из чата

Партнёры присылают часть документов по клиентам не в карточку, а в переписку.
Раздел «Документы из чата» собирает такие файлы в одну очередь, чтобы
администратор вручную привязал их к нужному клиенту. После привязки файл
проходит обычный путь документа: карточка клиента → комплект → Диск Битрикс24
и таймлайн сделки.

## Как это работает

1. Любой файл, отправленный в чат (кроме сообщений бота), попадает в очередь
   `/admin/documents-inbox` со статусом «на разборе».
2. Партнёр определяется по чату, поэтому клиента можно выбрать только среди
   клиентов этого партнёра.
3. Кабинет подсказывает кандидатов: сравнивает фамилию из имени файла и текста
   сообщения с ФИО клиентов партнёра. Подсказка ничего не привязывает
   автоматически.
4. Администратор выбирает клиента и тип документа, при необходимости снимает
   галочку «Отправить в Битрикс24», и нажимает «Прикрепить».
5. Файл копируется в хранилище документов, создаётся запись `file_uploads`,
   запускается штатная синхронизация с Битрикс24. В чат уходит системное
   сообщение о том, что документ принят, — партнёр видит результат.
6. Файл можно убрать из очереди кнопкой «Не документ» (скриншоты, переписка,
   служебные файлы).

## Переименование при привязке

В диалоге привязки поле «Имя документа» предзаполнено исходным именем.

- расширение показывается отдельным чипом и не редактируется; смена расширения
  отклоняется сервером с кодом 400;
- запрещённые символы `\ / : * ? " < > |` заменяются на пробелы;
- пустое имя не принимается;
- лимит 120 символов, расширение сохраняется;
- «Вернуть исходное» возвращает имя из чата.

Новое имя используется в карточке, в комплекте и в имени файла на Диске
Битрикса. Сообщение в чате не переименовывается; системная отметка содержит
исходное и новое имя. Если такой же файл уже есть у клиента (совпадение
SHA-256), привязка идёт к существующему документу и его имя не меняется.

## Статусы

| Статус | Значение |
| --- | --- |
| `unassigned` | Файл ждёт разбора |
| `assigned` | Привязан к клиенту, создан документ |
| `ignored` | Отмечен как «не документ» |

Статус хранится в `chat_attachment_assignments` — одна запись на сообщение
(у сообщения не больше одного вложения).

## API

Все методы доступны только роли `admin` и находятся в `/api/v1/admin/chat`.

- `GET /document-inbox?status=unassigned&partner_id=&search=&page=&page_size=`
- `GET /document-inbox/count` — счётчик для бейджа в меню
- `GET /document-inbox/items/{message_id}` — карточка файла (для перехода из чата)
- `POST /document-inbox/items/{message_id}/assign` — `{client_id, document_type, sync_to_bitrix}`
- `POST /document-inbox/items/{message_id}/ignore`

## Правила и ограничения

- Клиент должен принадлежать партнёру из чата, иначе `403`.
- Тип документа — из фиксированного списка (`passport`, `snils`, `inn_certificate`
  и т.д.). Тип влияет на проверку готовности комплекта.
- Если у клиента уже есть документ с таким же содержимым (совпадает SHA-256),
  новый файл не создаётся: сообщение связывается с существующим документом.
- Повторная привязка того же сообщения возвращает `409`, привязка после
  «не документ» — тоже.
- Удаление сообщения в чате не удаляет созданный документ; удаление документа
  в карточке не трогает сообщение и копию в Битрикс24 (она остаётся в CRM по
  задумке).
- Файлы в чате и документы клиента лежат в одном bucket MinIO; привязка делает
  копию объекта, чтобы удаление одной сущности не ломало другую.
