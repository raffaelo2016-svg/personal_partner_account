# Как работать с git и откатываться назад

Короткая памятка для повседневной работы. Ничего запоминать не нужно — все
команды есть ниже.

## Что где лежит

| Ветка | Назначение | Что происходит при отправке |
|---|---|---|
| `main` | Рабочая версия на проде | **Запускается автовыкладка на сервер** (`deploy.yml`) |
| `dev` | Повседневная работа | Ничего не выкладывается, код просто сохраняется на GitHub |
| `wip/*` | Снимки «как было» | Ничего не выкладывается |

Правило: **в `main` попадает только проверенный код**. Эксперименты — в `dev`.

## Начать работу

```bash
git switch dev
git pull
```

## Сохранить изменения

```bash
scripts/git-save.sh "что именно сделал"
```

Скрипт сам добавит изменения, сделает коммит и отправит ветку на GitHub.
Секреты (`backend/.env`) и внутренние документы (`КАД_*.xlsx`, выгрузка
Битрикс24 и прочее из `.gitignore`) в отправку не попадают.

## Посмотреть точки отката

```bash
scripts/git-restore.sh
```

Покажет метки `restore-*` и последние сохранения.

## Откатить назад

```bash
scripts/git-restore.sh restore-2026-11-06
```

Дальше скрипт предложит два варианта:

1. **Создать ветку от этой точки** — безопасно: текущая работа остаётся, можно
   сравнить и вернуться.
2. **Откатить текущую ветку** — жёсткий откат, всё сделанное после точки уйдёт
   из ветки (сама точка и её тег остаются).

## Поставить свою точку отката

Перед рискованными изменениями:

```bash
git tag -a restore-$(date +%Y-%m-%d) -m "перед переделкой кабинета"
git push origin --tags
```

## Выложить на прод

Только когда всё проверено:

```bash
git switch main
git pull
git merge --no-ff dev
git push origin main      # здесь запустится выкладка
```

## Если что-то пошло не так после выкладки

Откат на сервере делается через git на проде — выкладка идёт из `main`.
Быстрый вариант: вернуть `main` к предыдущему коммиту и запустить деплой
повторно:

```bash
git revert --no-edit <плохой-коммит>
git push origin main
```

## Полезно знать

- `.env` с настоящими паролями **не** хранится в репозитории. На сервере он
  лежит отдельно.
- Перед отправкой полезно проверить, что попадёт в коммит:
  `git status` и `git diff --stat`.
- Если push просит пароль или токен — нужно обновить вход:
  `gh auth login`.
